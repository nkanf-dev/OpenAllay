# OpenAllay

[English](README.md)

OpenAllay 是一个为整合包而生的现代化 Minecraft Agent。你只需自然地提问，
它就能理解任务、探索当前游戏中可用的数据、完成多步处理，并把结果整理成真正
有用的游戏内回答。

![OpenAllay 将 Skills、Extensions、共享模型、丰富界面与视觉引导带入 Minecraft](docs/media/openallay-banner.png)

*用一个伙伴，连接散落在整个整合包里的配方、系统、设置与知识。*

## Minecraft 里的现代化 Agent

OpenAllay 不只是一个聊天框，也不是一组写死的查询按钮。它把模型上下文、工具
调用、Skills 与内嵌 JavaScript 分析能力组合在一起。问题需要真实游戏数据时，
Agent 可以针对当前问题编写一段专用分析，一次比较完整的数据集合，再根据结果
继续完成任务。

因此，“把整合包里的剑按伤害排序”或“找出材料最少的容器配方”可以成为一次
完整分析，而不是让模型逐个物品查询几十轮。

### Skills 教会 Agent 如何完成任务

Skills 会为某个模组、玩法或问题类型提供渐进式指导。任务需要时，OpenAllay
会加载相关 Skill；简单问题则可以直接读取已经连接的游戏数据。目前内置 Skills
已经覆盖缺失配方诊断、模组机器、指南书、任务进度、跨页面游戏诊断与可选的
命令工作流。你也可以在游戏内浏览、安装和更新
[OpenAllay Skills 社区](https://github.com/nkanf-dev/OpenAllay-Skills)中的
工作流，或导入本地 Skill 安装包。

### Extensions 随整合包一起成长

OpenAllay Extensions 可以接入类型化游戏数据、可复用 JavaScript 模块、模组
集成与原生结果视图。游戏内的“扩展”页面会展示当前已经连接的能力，以及可供
Agent 使用的数据入口，还会列出
[OpenAllay Extensions 社区](https://github.com/nkanf-dev/OpenAllay-Extensions)
中的兼容安装包。社区 Extension 会像普通模组一样安装，并在重启游戏后生效。
你也可以直接导入兼容的本地 Extension JAR，不必等待它先进入社区目录。这样，
新模组集成可以持续成长，也不必把每种能力都做成另一个用途单一的工具。

### 独立 Extension 提供在线建造

OpenAllay 0.2.4 的 Fabric 和 NeoForge 下载包均包含 Minecraft Builder 扩展。
它来自
[OpenAllay-Extensions](https://github.com/nkanf-dev/OpenAllay-Extensions/tree/main/extensions/minecraft-builder)，
通过自己的 JavaScript 模块与 Skill 提供几何体、地形处理、六种预设建筑、
可保存的结构模板、旋转、镜像和带冲突检查的方块撤销。

在当前单人世界建造时，先选择本地模型，再在**设置 → 扩展**中显式开启
**无限制 JavaScript**。此设置默认关闭，与扩展安装分开管理。Builder 支持
生存与创造世界，撤销时会检查方块是否被后续操作改动。

Skill 与 Extension 详情会列出有用的能力和依赖。安装时可以启用可用需求、
取消，或选择 **Continue anyway（仍然继续）**，按当前权限安装该包。

### 为 Minecraft 而生的结果

回答可以包含物品图标、材料槽位、配方布局、表格、进度步骤和可展开详情。
类型化的 JavaScript 结果可以自动呈现为原生配方、物品或表格视图。JavaScript
工具卡片用简短标题和说明展示计划执行的工作，并单独显示执行状态与结果；
保存的会话也会保留这些说明。打开调试模式后，工具详情还会显示 Agent 提交的
JavaScript，以及这次调用的输入与输出。

### 模型由你选择

你可以连接兼容 OpenAI Chat Completions 或 Anthropic Messages 的服务，保存
多个模型配置，并直接在对话中切换。OpenAllay 既能用于单人游戏，也能在没有
安装本模组的普通多人服务器上使用；安装了 OpenAllay 的服务器还可以为玩家
提供共享模型和额外的服务端能力。连接后，共享模型会自动出现在**模型**页面，
并明确标注为服务器提供，与本地配置分开显示。

内置离线模型表可以为匹配的模型自动填写上下文窗口和最大输出，也适用于模型列表
仅提供 ID 的服务。你可以手动设置这两个预算，或清空字段恢复自动值。模型页面还会显示公开的 Token 参考价格、
价格档位、来源和日期，方便比较和选择模型。

### 随时可以继续的对话

把不同话题放进不同会话，回看保存的对话，复制有用的消息，或者导出完整会话。
实时状态会告诉你 Agent 正在加载指导、分析游戏数据、等待模型，还是执行操作。

## OpenAllay 0.2 可以做什么

- 用一段 JavaScript 关联并分析物品、配方、效果、标签、注册表、指南、设置与
  玩家可见的游戏状态。
- 对完整集合进行过滤、分组、排序、排行、汇总与比较，而不是每一轮只查询一个
  候选项。
- 渐进式发现当前可用的数据结构，包括兼容 Extensions 提供的类型化字段。
- 复用内置 JavaScript 模块，完成配方与背包计算等确定性的领域任务。
- 查看已安装模组、视频与游戏设置、资源包、坐标、维度和 F3 风格诊断信息。
- 查看一个聚焦区域内的方块或实体，再用 JavaScript 过滤、比较并核验观察结果，
  而不是把大量数据直接塞进对话。
- 搜索支持的指南书内容，并利用游戏本身、JEI、REI 和 Farmer's Delight 等
  配方丰富模组提供的信息。
- 把可信配方、物品、表格、简洁数值与通用结果呈现为数据驱动的原生视图。
- 在 OpenAllay 原生界面中使用多会话、持久历史、模型配置、复制、导出、停止与
  重试。
- 可选地把当前 Minecraft 命令集合交给 Agent 使用，其中也包括模组新增的命令；
  Agent 会先读取 Minecraft 返回的反馈，再说明实际发生了什么。这项实验性能力
  默认关闭，可以在**设置 → 扩展**中开启。

## 快速上手

请从 [Modrinth](https://modrinth.com/mod/openallay/versions) 或
[GitHub Releases](https://github.com/nkanf-dev/OpenAllay/releases) 下载最新的
OpenAllay **0.2.x** **Fabric** 或 **NeoForge** 版本。
0.2 系列面向 Minecraft **26.2**，需要 Java **25**；Fabric 玩家还需要安装
对应版本的 Fabric API。

把下载的 JAR 放入游戏实例的 `mods` 文件夹，启动 Minecraft，然后连接模型：

1. 进入一个世界，按 **K**，或输入 `/guide`。
2. 点击齿轮按钮，打开**模型**页面。
3. 添加一个 **OpenAI 兼容 Chat Completions** 或 **Anthropic Messages**
   配置。
4. 填写服务地址、模型 ID 和 API 密钥。
5. 检查自动匹配的上下文窗口，或手动填写，然后保存。
6. 在对话页顶部选择刚刚添加的配置，开始提问。

如果 Fabric 整合包包含 Architectury，请使用 **21.0.4**，以便在 OpenAllay
界面正常输入文字。**21.0.2 及更早版本**会导致文字输入失效。

## 可以这样问

- “我安装了哪些模组？它们分别是什么版本？”
- “这个整合包里基础伤害最高的剑是哪一把？”
- “能合成的容器中，哪一种需要的材料总数最少？”
- “苹果酒怎么做？我背包里的材料够吗？”
- “把农夫乐事里的所有食物按营养值比较一下。”
- “当前启用了哪些资源包？”
- “显示我现在的坐标、维度和 F3 信息。”
- “在已安装的指南书中搜索魔法作物。”
- “这个整合包里的药水效果有哪些可查询字段？”

打开实验性命令能力后，你也可以让 OpenAllay 执行当前可用的 Minecraft 命令，
读取游戏返回的真实反馈，并区分“已经得到确认”和“没有收到可见回复”。

## 使用游戏内界面

OpenAllay 会在一个不暂停游戏的 Minecraft 界面中打开。

- 按 **Enter** 发送消息；按 **Shift+Enter** 换行。
- **停止**会取消当前请求；**重试**会重新发起请求。
- 按 **Escape** 只会关闭界面。再次打开后，仍能看到继续生成的回答。
- 点击工具卡片，可以查看这次调用的输入与实际输出。
- 想查看 Agent 编写的 JavaScript 与完整实时诊断时，可以打开**调试模式**。
- 可以用不同会话区分话题，也可以随时切换到另一个已配置的模型。

## 模组与内容支持

OpenAllay 会利用当前整合包中已经存在的内容：

- **JEI** 配方可以在 OpenAllay 中使用熟悉的 JEI 布局。
- **REI** 可以为 OpenAllay 的配方体验提供配方信息。
- 可以直接在游戏中搜索当前资源里的 **Patchouli** 指南书内容。
- **Farmer's Delight** 等配方丰富的模组可以使用配方分析、材料检查和可视化
  配方页面。
- 当对应集成可用时，模组新增的注册表、字段与命令可以通过类型化 Extensions
  和命令目录被发现。

这些集成都不是必需项。即使其中某项没有安装，或不适用于当前环境，OpenAllay
仍然可以继续使用。


## 当前开发状态

正式 1.0 之前，内部格式采用 **Latest Only**。随 OpenAllay 一起原子发布的代码和
格式不设内部 schema／协议版本号，也不保留旧版兼容层。独立发布的 Extension
及其公开 API 仍保留必要的版本契约。

当前源码重构取消 JavaScript 根节点声明，以及“必须先读取游戏数据才能成功执行”
的要求；跨轮保留真实工具结果、错误和已加载的 Skill 正文，将原始历史与压缩后的
模型上下文分开保存，并将可选来源信息分组展示。Builder 改为批量扫描、地形准备、
建造和撤销，使用增量操作日志。确定性测试和双加载器构建已通过；这些说明不代表
已发布的 0.2.4 文件已经更新，也不代表已测得游戏内耗时。内部格式不迁移，也不会自动清空
现有本地测试数据。

## 路线图

OpenAllay 正在成长为一个面向 Minecraft 的开放 Agent 平台：

- **OpenAllay Skills** —— 由玩家、整合包作者与社区创作、改进和分享的工作流
  与领域知识，并且可以直接在游戏内安装。
- **OpenAllay Extensions** —— 新的游戏数据适配器、可复用模块、模组集成、
  Agent 能力与原生结果体验，以熟悉的模组安装包形式分发。
- **OpenAllay Host** —— 为服务器与社区提供共享模型和统一管理的 Agent 服务。
- **OpenAllay Studio** —— 用来创作丰富游戏内体验、动态界面与可复用视觉引导
  的创作环境。

### 接下来

- 可以由玩家查看、纠正、固定或遗忘的玩家记忆。
- 更顺畅的 Skills 与 Extensions 创作、编辑、审核与发布流程。
- 更多第一方数据适配器、知识来源与模组集成。
- 带有玩家审批体验的实验性操作能力。

### 更长远的方向

- 把目前聚焦区域的方块与实体观测扩展到地图、结构、容器和更丰富的周边环境
  理解。
- 把结构与文档变成分步骤视觉教程，并在有兼容集成时提供 Ponder 风格引导。
- 跨机器、中间材料与大型科技树规划完整生产链。
- 持续发展 OpenAllay Host、Studio 与更广泛的社区生态。

OpenAllay 是独立项目，与 Mojang Studios 或 Microsoft 没有从属关系，也未获得
其认可。
